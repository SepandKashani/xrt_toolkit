The X-ray transform
===================

Definition and discretisation
-----------------------------

The library discretises the X-ray transform of a function
:math:`f: \mathbb{R}^{D} \to \mathbb{R}`, :math:`D \in \{2, 3\}`, along a ray
parameterised by a point :math:`\mathbf{t}` and a direction :math:`\mathbf{n}`:

.. math::

   (\mathbf{A} f)(\mathbf{t}, \mathbf{n})
   = \int_{\mathbb{R}} f(\mathbf{t} + \alpha \mathbf{n}) \, \mathrm{d}\alpha .

The volume is not a black box: :math:`f` is expanded on a shifted basis on a
uniform lattice :math:`\mathbf{x}_{\mathbf{q}} = \mathbf{x}_{0} +
\mathbf{q} \odot \boldsymbol{\Delta}`,

.. math::

   f(\mathbf{x}) = \sum_{\mathbf{q}} f_{\mathbf{q}} \,
                   \psi(\mathbf{x} - \mathbf{x}_{\mathbf{q}}),

so the transform becomes a sparse matrix acting on the coefficients
:math:`f_{\mathbf{q}}`, with entries given by the *projected* basis
:math:`\int \psi(\mathbf{t} + \alpha \mathbf{n}) \mathrm{d}\alpha`. That
integral is what the traversal kernel evaluates analytically, cell by cell.

Basis functions
---------------

:math:`\psi` is a box spline of order 0, 1 or 2, selected with the ``order``
argument. Order 0 is the voxel indicator, so the matrix entries are exactly the
chord lengths of the ray inside each cell (Siddon's classic case); higher orders
are smoother and their projections have wider support. Each figure below shows
the support of :math:`\psi` on the lattice and its 1-D projections at several
directions — generated by :py:func:`~xrt_toolkit.plot_2d_basis`.

The adjoint
-----------

:py:func:`~xrt_toolkit.xrt_adjoint` is the *exact transpose* of
:py:func:`~xrt_toolkit.xrt_apply`, not an approximation of the backprojection
integral: the same traversal visits the same cells with the same weights and
scatters instead of gathering. That is what makes the pair usable inside
iterative solvers, where :math:`\langle \mathbf{A} f, y \rangle =
\langle f, \mathbf{A}^{\top} y \rangle` must hold to machine precision (the
test suite checks it).

.. figure:: _static/forward_adjoint.png

   An image, its sinogram, and the unfiltered backprojection of that sinogram.
   The backprojection is blurred by :math:`1/r`: undoing that blur is what
   filtering does.

Filtered backprojection
-----------------------

The inversion formula for a parallel scan filters each projection with the ramp
:math:`|\sigma|` before backprojecting,

.. math::

   f = \frac{\pi}{N_{\text{proj}}} \sum_{\theta}
       \mathbf{A}_{\theta}^{\top} \left( h * p_{\theta} \right),
   \qquad \hat{h}(\sigma) = |\sigma| \, w(\sigma),

where :math:`w` is a smoothing window (``"ramp"``, ``"shepp-logan"``,
``"cosine"``, ``"hamming"``, ``"hann"``). The library builds :math:`h` as the
discrete Kak & Slaney kernel on a padded grid, which keeps its DC component
exactly zero, and stops the ramp at the frequency the *reconstruction lattice*
can represent — with a detector finer than the lattice, everything above that
can only alias.

For divergent scans :py:func:`~xrt_toolkit.fbp_cone` applies the FDK recipe:
cosine pre-weighting :math:`\mathrm{sdd}/\sqrt{\mathrm{sdd}^2 + u^2 + v^2}`,
the same ramp along the in-plane axis, then a distance-weighted backprojection.
FDK is exact in the mid-plane only: a circular source orbit violates Tuy's
condition off it, and the resulting artifacts grow with the cone angle.

.. figure:: _static/reconstruction.png

   The same data reconstructed analytically and iteratively. On noiseless,
   self-consistent data the iterative solution wins; with noise the ranking
   flips and it must be stopped early.

Geometry derivatives
--------------------

Because the projected basis is differentiable in the ray parameters, so is the
whole transform. :py:func:`~xrt_toolkit.xrt_ad_t_x` and its siblings return

.. math::

   \frac{\partial}{\partial t_{i}} (\mathbf{A} f), \qquad
   \frac{\partial}{\partial n_{i}} (\mathbf{A} f),

which is what lets the acquisition geometry itself be calibrated by gradient
descent — see the differentiation section of the 2-D tutorial.
